# Production Prompt → App Flow\n\nThe production product is a chat-driven autonomous builder.\n\n## User experience\n\nThe user types one request in chat, for example:\n\n> Make a habit tracker for me by following current app trends respectively.\n\nThe system then performs:\n\n1. Research current public web/app information and extract relevant UI, UX, feature, and implementation patterns.\n2. Plan the application from the prompt and research.\n3. Create a GitHub repository using the connected GitHub account.\n4. Generate project files directly into GitHub and commit them.\n5. Test the repository and inspect the result.\n6. Repair failures, commit corrections, and re-test.\n7. Deploy the committed repository to Vercel.\n8. Verify the live deployment.\n9. Return the verified URL to the same chat.\n\n## Credential rule\n\nThe production flow does not require the user to supply additional API keys. Research uses connected Composio search/browser capability; GitHub uses the connected GitHub account; Vercel uses the connected Vercel account; and the host ChatGPT/agent performs reasoning/orchestration. Generated applications never receive these credentials.\n\n## Source of truth\n\nGitHub is the source of truth for generated applications. Vercel deploys from the committed repository rather than a temporary local directory.\n\n## Free-first constraint\n\nThe MVP prefers free tiers and does not introduce a paid API dependency. Future paid providers must remain optional.\n\n## Failure policy\n\nCapture test failures, repair only affected files, commit, re-test, and stop after a bounded number of attempts. Only a verified live URL is reported as successful.\n
